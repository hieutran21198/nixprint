# Feature Documents

## Purpose

This document defines the boundaries of feature documentation.

## Requirements

Requirements define the intended outcome, need, constraints, and acceptance
criteria. They MUST state what is needed. They MUST NOT define solution design
or task breakdown.

## Specifications

Specifications define required behavior, interfaces, data, rules, and quality
attributes. They MUST satisfy related requirements. They MUST NOT record the
history of a chosen option or work status.

## Decisions

Decisions record accepted significant choices. A decision MUST state its
context, considered options, chosen outcome, rationale, and consequences.

A decision MUST NOT become a design guide or a full specification. An accepted
decision MUST preserve its historical content. A later accepted decision MUST
identify the decision that it supersedes.

## Implementation Plans

Implementation plans define the approved execution approach. They MUST describe
change sequence, dependencies, risks, and verification approach. They MUST NOT
duplicate detailed task status.

## Tasks

Tasks define the work required to implement the feature. They MUST be actionable
and traceable to the implementation plan. They MUST NOT own work status.

The execution system owns work status. A task MAY link to an execution-system
record.
